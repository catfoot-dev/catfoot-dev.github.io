최근 개발자들과 이야기를 나누다 보면 AI에 대한 관심은 매우 높지만, 막상 "AI를 개발에 어떻게 활용해야 하는가"라는 질문에서는 이야기가 조금 달라진다.

ChatGPT나 Claude 같은 서비스를 업무에 활용하거나 GitHub Copilot과 같은 도구로 코드를 작성하는 것은 이제 꽤 익숙해졌다. 하지만 직접 LLM을 이용해 서비스를 만든다고 하면 프롬프트 작성 이후 무엇을 해야 하는지 막막하게 느끼는 개발자도 적지 않다.

나 역시 게임 업계를 포함해 여러 IT 기업에서 약 14년 동안 서버 개발을 해왔지만 AI 분야에서는 다시 새로운 기술을 공부하는 입장이다. 최근에는 생성형 AI와 AI 에이전트에 관심을 가지고 조금 더 깊게 공부하고 있는데, 주변 개발자들과 AI를 실제 개발에 어떻게 활용할 수 있을지 이야기하기 위한 세미나도 준비하고 있다.

그 과정에서 세미나의 중심 교재로 선택한 책이 길벗에서 출간한 김기수 저자의 "AI 자율학습 처음 만드는 AI 에이전트 서비스"다.

이 책을 선택한 가장 큰 이유는 **AI 기능을 하나의 웹 서비스로 완성하는 전체 과정**을 보여주기 때문이다.

## AI를 공부할 때 생각보다 자주 마주치는 문제

생성형 AI 공부를 처음 시작하면 대부분 비슷한 순서를 경험한다.

OpenAI나 다른 LLM의 API를 호출해 보고, 프롬프트를 변경하면서 결과를 비교해 본다. 조금 더 공부하면 LangChain과 같은 프레임워크를 사용해 체인을 만들고 출력 형식을 구조화한다.

여기까지는 비교적 빠르게 따라갈 수 있다.

그런데 실제 서비스를 만들려고 하면 상황이 달라진다.

```
"사용자의 요청에 따라 여러 기능 중 어떤 기능을 실행할 것인가?"

"LLM이 만든 결과를 백엔드에서 안정적으로 처리하려면 어떻게 해야 하는가?"
```

AI 개발이 어려운 이유는 이런 질문들이 한꺼번에 등장하기 때문이다.

이 책은 LangChain을 이용한 기본적인 LLM 호출과 프롬프트 설계에서 시작해 LCEL, 구조화된 출력, Tool 구현, AI 에이전트 개발을 거쳐 FastAPI 백엔드와 React 프런트엔드, 그리고 최종 서비스 배포까지 이어진다.

이런 구성은 서버 개발자에게 상당히 익숙한 방식이다. 기존에 알고 있던 애플리케이션 개발 과정 안에 AI를 하나씩 끼워 맞추는 것 같았다.

## '에이전트'를 만들어 본다

이 책에서 소개하는 것은 사용자가 입력한 글을 분석하는 AI 글 분석 서비스다.

서비스에는 글 요약, 감성 분석, 재작성 기능이 각각 Tool로 구현되어 있다. 중요한 점은 사용자가 각각의 기능을 직접 선택하는 구조가 아니라, 에이전트가 사용자의 요청을 판단해 적절한 Tool을 선택하도록 만든다는 것이다.

단순한 LLM 서비스라면 입력된 내용을 프롬프트에 넣고 결과를 반환하는 구조로도 충분하다. 하지만 에이전트에서는 현재 상황을 판단하고 필요한 기능을 선택하는 일종의 컨트롤러 역할까지 맡는다.

예를 들어 사용자가 글의 내용을 짧게 정리해 달라고 요청하면 요약 Tool을 사용할 수 있고, 문장의 분위기를 분석해 달라고 요청하면 감성 분석 Tool을 선택할 수 있다. 문장을 다른 스타일로 바꾸어 달라는 요청에서는 재작성 Tool을 사용할 수 있다.

서버 개발자의 관점에서 보면 이 구조가 상당히 흥미롭다.

일반적인 애플리케이션에서는 개발자가 조건문과 비즈니스 로직을 통해 어떤 기능을 호출할지 결정하는데, 에이전트 구조에서는 일부 판단을 LLM에 위임한다.

**LLM을 단순한 텍스트 생성기가 아니라 애플리케이션의 실행 흐름을 결정하는 구성 요소로 사용하기 시작하는 것이다.**

## LangChain과 LCEL을 순서대로 따라가자

AI 관련 예제 코드를 찾아보면 LangChain 코드가 자주 등장하지만, 처음 접하면 코드 몇 줄이 내부적으로 무엇을 하는지 이해하기 어려운 경우가 있다.

이 책에서는 LLM 호출부터 메시지를 이용한 역할과 맥락 전달, PromptTemplate과 ChatPromptTemplate을 이용한 프롬프트 구조화, Runnable과 LCEL을 이용한 처리 흐름 연결까지 단계적으로 진행한다. 이후 출력 데이터를 구조화하고 입력 유지와 병렬 처리까지 확장한다.

이 과정을 거친 다음 Tool과 Agent로 넘어가기 때문에 전체 흐름을 이해하기 좋다.

실제 서비스를 개발하려면 LLM이 반환하는 자연어 결과를 그대로 사용하기 어려운 경우가 많다. 프런트엔드와 백엔드는 일정한 데이터 구조를 기대하기 때문이다.

책에서는 LCEL과 출력 데이터 구조화를 이용해 LLM의 결과를 애플리케이션에서 다룰 수 있는 형태로 연결하는 과정을 다룬다.

AI 기능 역시 결국 서비스의 일부이고, 서비스 안에서는 입력과 출력의 형태, 오류 처리, API 규격과 같은 기존 소프트웨어 엔지니어링 문제가 그대로 존재하기 때문이다.

## FastAPI에서 React, 배포까지 이어진다

AI 입문 자료 가운데 상당수는 Python 파일이나 Jupyter Notebook에서 모델을 호출하고 결과를 확인하는 수준에서 끝난다.

학습 단계에서는 충분하지만 그다음 단계로 넘어가려 하면 갑자기 많은 것을 스스로 연결해야 한다.

이 책에서는 AI 에이전트를 만든 이후 FastAPI를 이용해 백엔드를 구축하고 `/api/analyze` API를 만든다. 요청과 응답 구조, 환경 변수, CORS, 오류 처리와 응답 표준화도 함께 다룬다. 이후 React와 Tailwind CSS를 이용해 프런트엔드를 만들고 API를 연결한 다음 서비스를 배포하는 과정까지 진행한다.

사용자가 React 화면에서 요청을 입력하고, FastAPI 서버가 요청을 전달받는다. 서버 내부에서는 LangChain 기반의 에이전트가 요청을 판단해 적절한 Tool을 실행하고, 처리된 결과를 다시 화면으로 전달한다.

기존 웹 개발자나 서버 개발자가 AI 분야에 입문할 때는 이런 방식이 효과적이라고 생각한다.

이미 알고 있는 HTTP API, 프런트엔드와 백엔드, 데이터 구조, 배포 개념과 그 위에 LLM, Tool, Agent라는 새로운 구성 요소를 추가하면서 이해할 수 있기 때문이다.

## 가볍게 읽기 좋은 책

이 책의 난이도는 입문 수준으로 소개되어 있으며, 약 300페이지 분량 안에서 LangChain부터 풀스택 웹 서비스와 배포까지 상당히 넓은 영역을 다룬다. 요즘 IT 서적에서 300페이지라고 하면 그렇게 많은 페이지는 아니다. 실제로 책이 얇은 편이기도 하다.

그래서 이미 웹 서비스를 오래 개발해 온 개발자라면 FastAPI나 React의 기본적인 프로젝트 구성처럼 일부 내용은 비교적 빠르게 읽을 수 있을 것이다.

익숙한 부분은 빠르게 넘어가고, LangChain, LCEL, Tool Calling, Agent와 같이 새롭게 익혀야 하는 부분에 집중할 수 있기 때문이다.

또 하나 좋았던 점은 AI를 지나치게 거대한 개념으로 접근하지 않는다는 것이다.

최근에는 Multi-Agent, RAG, MCP, Agentic Workflow 등 새로운 용어가 매우 빠르게 등장한다. 처음 AI를 공부하는 입장에서는 무엇부터 시작해야 할지 어려울 수 있다. 결국 이러한 기술을 이해하려면 먼저 하나의 LLM을 호출하고, 프롬프트를 구성하고, 데이터를 구조화하고, Tool을 만들고, LLM이 Tool을 선택하도록 하는 기본 구조를 이해해야 한다.

이 책은 그 기본적인 연결 과정을 직접 만들어 보도록 구성되어 있다.

## AI를 어떻게 공부해야 할지 고민하는 개발자에게

AI 개발 역시 결국 소프트웨어 개발이다.

LLM이라는 새로운 구성 요소가 등장했지만 서비스를 만드는 기본적인 고민이 완전히 사라진 것은 아니다.

기능을 어떻게 나눌 것인지, 데이터는 어떤 구조로 전달할 것인지, 외부 기능은 어떻게 호출할 것인지, 오류는 어떻게 처리할 것인지, 사용자에게 결과를 어떻게 보여줄 것인지 등을 여전히 설계해야 한다.

다만 기존에는 개발자가 모두 결정했던 일부 영역을 이제 LLM에게 맡길 수 있게 되었다. 그리고 바로 그 지점에서 기존 애플리케이션과 다른 새로운 서비스 구조가 만들어진다.

LangChain과 프롬프트부터 시작해 LCEL, Tool, Agent, FastAPI, React 그리고 배포까지 이어지는 과정은 "AI 공부를 시작했는데 그다음에 무엇을 해야 할지 모르겠다"는 개발자에게 추천한다.

특히 ChatGPT를 사용하는 단계에서 한 걸음 더 나아가 **직접 AI 기능을 설계하고 자신의 서비스 안에 에이전트를 넣어보고 싶은 개발자라면 한 번 읽어볼 만한 책**이라고 생각한다.

나 역시 이번 책을 세미나 주제로 선택하면서, 기존 서버 애플리케이션의 비즈니스 로직과 AI 에이전트의 판단 구조가 어떻게 달라지는지를 중심으로 동료 개발자들과 이야기해볼 생각이다.

AI 시대에 개발자의 역할이 사라진다기보다 개발자가 다루어야 할 새로운 구성 요소가 하나 더 생긴 것 같다. 개발자인데도 아직 AI를 어려워하고 있다면? 이 책으로 AI 에이전트 개발을 시작해보자.

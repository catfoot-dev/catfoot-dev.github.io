최근 개발자들과 이야기를 나누다 보면 AI에 대한 관심은 정말 높다. ChatGPT나 Claude를 업무에 활용하거나 GitHub Copilot으로 코드를 작성하는 것도 이제는 꽤 익숙한 풍경이 됐다.

그런데 “직접 LLM을 이용해서 서비스를 만들어보자”라고 하면 이야기가 조금 달라진다.

API를 호출하고 프롬프트를 작성하는 것까지는 해봤지만, 그다음에는 무엇을 해야 하는지 막막하다는 이야기를 주변에서도 자주 듣는다.

나 역시 게임 업계를 포함해 여러 IT 기업에서 약 14년 동안 서버 개발을 해왔지만, AI 분야에서는 다시 공부하는 입장이다. 최근에는 생성형 AI와 AI 에이전트에 관심을 두고 공부하고 있고, 동료 개발자들과 AI를 실제 개발에 어떻게 활용할 수 있을지 이야기하는 세미나도 준비하고 있다.

세미나에서 함께 볼 책을 찾다가 마침 길벗에서 출간한 "AI 자율학습 처음 만드는 AI 에이전트 서비스"를 출판사로부터 제공받아 읽어볼 기회가 생겼다.

## 프롬프트 다음에는 무엇을 해야 할까

생성형 AI를 처음 공부하면 대체로 비슷한 과정을 거친다.

OpenAI와 같은 LLM API를 호출해 보고, 프롬프트를 조금씩 바꿔가며 결과를 비교한다. LangChain을 알게 되면 체인을 만들어보거나 출력 형식을 구조화하는 예제도 따라 해본다.

그런데 예제에서는 결과가 잘 나오는데, 이것을 실제 서비스로 만들려고 하면 갑자기 고려할 것이 많아진다. 더 어려운 점은 LLM이 웬만하면 무언가를 출력해준다는 것이다. 결과가 나왔다는 사실만으로 지금 구현한 방식이 제대로 된 것인지 판단하기가 어렵다.

이 책에서는 기본적인 LLM 호출과 프롬프트 작성을 먼저 알려준다. 그 이후 LCEL, 구조화된 출력, Tool 구현, AI Agent를 차례로 다루고 FastAPI 백엔드와 React 프런트엔드, 서비스 배포까지 이어진다.

서버 개발자 입장에서는 이런 구성이 꽤 편했다.

AI를 완전히 새로운 영역으로 떼어놓고 설명하기보다, 평소 만들던 애플리케이션 안에 LLM과 Agent라는 새로운 요소를 하나씩 추가하는 느낌이었기 때문이다.

## 직접 에이전트를 만들어본다

책에서 만드는 예제는 사용자가 입력한 글을 분석하는 AI 서비스다.

글 요약, 감성 분석, 재작성 기능이 각각 Tool로 구현되어 있고, 사용자가 메뉴에서 기능을 직접 고르는 대신 Agent가 요청 내용을 보고 어떤 Tool을 사용할지 결정한다.

예를 들어 글을 짧게 정리해달라고 하면 요약 Tool을 사용하고, 문장의 분위기를 알고 싶다고 하면 감성 분석 Tool을 선택한다. 다른 스타일로 글을 바꿔달라는 요청이라면 재작성 Tool을 호출한다.

이 부분이 특히 재미있었다. 기존 애플리케이션에서는 개발자가 조건문이나 비즈니스 로직을 작성해 어떤 기능을 실행할지 결정했었는데 Agent를 사용하면 이런 판단의 일부를 LLM에게 넘길 수 있었다.

단순히 문장을 만들어주는 기능으로 사용하는 것과는 꽤 다른 접근이었다. 결정하는 역할까지 맡기기 시작했기 때문이다.

물론 모든 판단을 LLM에게 맡긴다는 의미는 아니다. 어디까지 맡길 것인지, 어떤 Tool을 제공할 것인지, 결과를 어떻게 검증할 것인지는 여전히 개발자가 설계해야 한다. 이 경계를 직접 구현하면서 확인해볼 수 있다는 점이 좋았다.

## LangChain과 LCEL을 차근차근 따라간다

AI 관련 예제 코드를 찾아보다 보면 LangChain 코드를 자주 만나게 된다.

처음 접했을 때는 코드 자체는 몇 줄 되지 않는데, 내부에서 무슨 일이 일어나는지 이해하기 어려웠다. 그래서 책에서는 처음부터 복잡한 Agent 코드를 보여주지 않는다.

LLM을 호출하는 방법부터 시작해 메시지로 역할과 맥락을 전달하고, PromptTemplate과 ChatPromptTemplate으로 프롬프트를 구성한다. 이후 Runnable과 LCEL을 이용해 처리 흐름을 연결하고, 출력 데이터를 구조화하거나 여러 작업을 병렬로 처리하는 방법까지 범위를 넓혀간다.

그 뒤에 Tool과 Agent가 등장한다. 순서대로 코드를 따라가다 보면 앞에서 만든 요소들이 Agent 안에서 어떤 역할을 하는지 자연스럽게 연결된다.

개인적으로는 이 흐름이 좋았다. AI 기능도 실제 서비스에 들어가면 입력과 출력 형식이 필요하고, API 규격을 정해야 하며, 오류 처리도 해야 한다. 기존 애플리케이션을 만들 때 하던 고민이 그대로 남아 있기 때문이다.

## FastAPI와 React를 연결해 서비스 형태로 만든다

AI를 공부할 때 Python 파일이나 Jupyter Notebook에서 모델을 호출해보고 끝나는 경우가 많다.

개념을 익히는 데는 충분하지만, 막상 다른 사람이 사용할 수 있는 형태로 만들려고 하면 API부터 화면, 환경 변수, 오류 처리, 배포까지 직접 연결해야 한다.

이 책에서는 Agent를 만든 뒤 FastAPI로 백엔드를 구성하고 `/api/analyze` API를 만든다. 요청과 응답 구조를 정의하고 환경 변수, CORS, 오류 처리, 응답 형식 같은 내용도 함께 다룬다.

그다음에는 React와 Tailwind CSS로 화면을 만들고 앞에서 만든 API를 연결한다. 마지막에는 실제 배포 과정까지 진행한다.

전체 구조를 보면 일반적인 웹 서비스와 크게 다르지 않다. 웹이나 서버 개발 경험이 있는 사람이라면 이 방식이 AI를 이해하는 데 꽤 도움이 될 것 같다.

HTTP API나 프런트엔드와 백엔드의 역할을 새로 공부할 필요 없이, 기존에 알고 있던 구조 위에 LLM, Tool, Agent가 어디에 들어가는지만 살펴보면 되기 때문이다.

## 부담 없이 따라가기 좋은 분량

책은 약 300페이지 정도다. IT 서적치고 300페이지가 그렇게 많은 분량은 아니지만, 그렇기 때문에 가볍게 읽기 좋았다. 실제로 두께도 얇다.

그래서 모든 내용을 깊게 파고드는 책이라기보다는 전체 흐름을 한 번 경험해보는 데 초점이 맞춰져 있다.

최근 AI 분야를 보다 보면 Multi-Agent, RAG, MCP, Agentic Workflow처럼 새로운 용어가 계속 등장한다. 처음 공부하는 입장에서는 어디서부터 시작해야 할지 오히려 더 헷갈린다.

그런 부분을 싹다 빼고 기본적인 기능인 AI 에이전트에 집중하기 때문에 부담이 없다.

## AI 서비스를 직접 만들어보고 싶은 개발자에게

LLM이 등장했다고 해서 서비스 개발 방식이 완전히 바뀐 것은 아니다.

어떤 기능을 만들 것인지 정해야 하고, 데이터를 어떤 형태로 주고받을지 설계해야 한다. 외부 기능과 어떻게 연결할지, 오류가 발생했을 때 어떻게 처리할지, 결과를 사용자에게 어떤 형태로 보여줄지도 고민해야 한다.

달라진 점이 있다면 개발자가 직접 코드로 작성하던 판단 중 일부를 LLM에게 맡길 수 있게 됐다는 것이다. 어떤 요청인지 판단하고, 사용할 Tool을 선택하고, 필요한 작업을 이어가는 과정에 LLM이 참여한다.

이 책은 프롬프트 작성법만 공부하다가 그다음 단계로 넘어가고 싶은 개발자에게 잘 맞는 책이라고 생각한다. LangChain과 LCEL부터 Tool, Agent, FastAPI, React, 배포까지 한 번에 따라가기 때문에 각 기술을 깊게 공부하기 전에 전체적인 그림을 잡는 용도로도 꽤 괜찮다.

AI가 아직 낯선 개발자라면 너무 거창한 것부터 시작할 필요는 없다. 이 책으로 작은 Agent 하나를 직접 만들어보는 것부터 시작해봐도 좋겠다.
